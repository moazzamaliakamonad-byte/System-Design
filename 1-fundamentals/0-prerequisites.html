The Physical Hardware

1. Nodes, Instances & Clusters

System design uses a lot of fancy words to describe what is essentially just a computer sitting in a dark room.

  • Node / Instance: A single running server (a computer). When someone says "spin up a new node" or "reboot the EC2 instance", they just mean turn on one computer.
  • Cluster: A group of Nodes working together as a team. To the outside world, a cluster looks like one giant, powerful computer. If one node in the cluster dies, the others pick up the slack.
  • Client: The thing asking for data. This is usually your web browser (Chrome), your mobile app, or another server.
  • Server: The thing providing the data. It literally "serves" you what you asked for.

Memory and Scalability

2. Stateful vs. Stateless

This is the secret to scaling web servers. "State" is just a fancy word for "memory" or "data about the current user."

🦉
Stateful (The Elephant): The server remembers you between requests. If you log in on Request 1, the server stores your user ID in its own local RAM. When you make Request 2, it knows who you are.

Stateless (The Goldfish): The server has amnesia. Every single request is treated as a brand new interaction. If you want the server to know you are logged in, you must send your ID/Token with every single request.

Why does this matter? If your system is Stateful, and Node A remembers you, what happens when Node A crashes? You get logged out. If your system is Stateless, any node (Node A, B, or C) can handle your request because the node doesn't need to remember you. This makes scaling infinitely easier.

Communication

3. Synchronous vs. Asynchronous

How do computers talk to each other? Just like humans, they have two methods:

  • Synchronous (Blocking): Like a phone call. I talk, you listen. I ask you a question, and I wait on the line doing nothing until you give me the answer. If you take 10 seconds to answer, I am blocked for 10 seconds.
  • Asynchronous (Non-Blocking): Like a text message. I ask you a question, hit send, and go make a sandwich. You can reply whenever you finish processing it. My life is not blocked waiting for you.

Hardware Basics

4. Memory (RAM) vs. Disk

When we talk about databases and caches in the upcoming files, you must understand the physical difference in hardware:

⚠️
RAM (Memory): Lightning fast. But it is volatile. If the server loses power or restarts, everything in RAM is deleted instantly. This is where Caches (like Redis) live.

Disk (SSD/HDD): Much slower. But it is persistent. If the server loses power, the data survives. This is where Databases (like PostgreSQL) live.
