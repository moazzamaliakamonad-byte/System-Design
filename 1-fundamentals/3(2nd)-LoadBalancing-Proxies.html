Load Balancing Depth

Layer 4 vs Layer 7 Load Balancing

Load balancers operate at different levels of the OSI stack. Choosing between them dictates your latency, cost, and routing capabilities.

Layer 4 Load Balancer (The High-Speed Pipe)

Operates at the transport layer. It looks only at the raw TCP/UDP packets (IP addresses and port numbers) without inspecting the actual application data inside.

  • Pros: Extremely fast, handles massive throughput with minimal CPU overhead, completely protocol-agnostic (can balance database traffic, game servers, or web traffic).
  • Cons: Cannot route based on URL paths (e.g., cannot send /images/* to one server cluster and /api/* to another).

Layer 7 Load Balancer (The Smart Router)

Operates at the application layer. It terminates the client connection, reads the actual HTTP/HTTPS headers, cookies, and URL paths, and makes intelligent routing decisions.

  • Pros: Path-based routing (/checkout vs /search), header manipulation, cookie-based session affinity, and Web Application Firewall (WAF) integration.
  • Cons: Higher CPU overhead because it must decrypt TLS/SSL and parse application payloads.

Security & Performance

Reverse Proxies & SSL Termination

A Reverse Proxy sits in front of backend servers, intercepting client requests. While a load balancer focuses primarily on spreading volume, a reverse proxy focuses on security, anonymity, and performance optimization.

🔒
SSL/TLS Termination: Encrypting and decrypting HTTPS traffic is computationally heavy. By performing SSL termination at the reverse proxy layer, your internal backend microservices can communicate over plain, lightning-fast HTTP internally, offloading all cryptographic overhead.

Microservices Architecture

API Gateways

In a microservices architecture, you might have 50 different internal services (Users, Orders, Payments, Search). You don't want mobile apps and web clients trying to connect to 50 different IP addresses and handling 50 different authentication schemes.

An API Gateway is a specialized reverse proxy that acts as the single entry point for all clients. It handles:

  • Centralized Authentication: Validating JWT tokens or API keys before requests ever touch internal services.
  • Rate Limiting & Throttling: Rejecting clients who spam requests (e.g., max 100 requests per minute).
  • Protocol Translation: Translating external HTTP/JSON requests into internal high-performance gRPC calls.

Production Config

Nginx Reverse Proxy & Load Balancer Config

A real-world production Nginx configuration file demonstrating upstream server load balancing, path-based routing, and SSL termination.

Nginx Configuration
# Define backend server pool for load balancing
upstream backend_cluster {
    server 10.0.1.10:8080 weight=3;
    server 10.0.1.11:8080;
    server 10.0.1.12:8080 backup;
}

server {
    listen 443 ssl;
    server_name api.production.com;

    # SSL/TLS Termination
    ssl_certificate /etc/certs/fullchain.pem;
    ssl_certificate_key /etc/certs/privkey.pem;

    # Path-based routing to backend cluster
    location /api/v1/ {
        proxy_pass http://backend_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_connect_timeout 5s;
    }
}

1. What is the primary operational difference between a Layer 4 and a Layer 7 Load Balancer?
✓ Layer inspection scope. Layer 4 balances raw packets at transport speed, whereas Layer 7 understands application content (like URL paths and cookies) to route smartly.
2. Why do production environments implement SSL/TLS Termination at the Reverse Proxy layer?
✓ Offloading compute. Decrypting HTTPS for every single user is computationally expensive. Terminating it at the edge lets internal services communicate efficiently over plain HTTP.
3. Which system design component is primarily responsible for cross-cutting business concerns like rate limiting, JWT token validation, and request routing across dozens of microservices?
✓ API Gateway. It acts as the centralized manager handling API-specific policies, authentication, and orchestration before requests reach internal teams.
4. What is a key benefit of a Reverse Proxy hiding internal backend server IP addresses from public clients?
✓ Infrastructure Anonymity. Attackers cannot directly target backend instances if they only interact with the public proxy facade.
