The Bottleneck

1. The Naive Approach (And Why It Fails)

Let's imagine we want to find the perfect video for a user. The simplest approach is to build a Machine Learning (ML) model that takes in a [User Profile] and a [Video Metadata], and outputs a match percentage[cite: 11].

Naive Logic
Video_1 Match: 93% [cite: 14]
Video_2 Match: 83% [cite: 14]
Video_3 Match:  2% [cite: 14]
...
# Sort descending, show top 10 to user

The Catastrophic Flaw: Scale. We have billions of videos on the platform[cite: 14]. If our heavy ML model takes just 1 millisecond to score a single video, evaluating 1 billion videos for a single user would take 11.5 days of compute time[cite: 14] just to load their homepage!

Running a deep neural network on billions of videos requires an insane amount of resources[cite: 14]. Doing this in real-time is physically impossible unless you possess a "data center the size of a state"[cite: 14]. We need a better way.

Modern System Design

2. The Modern System: The Funnel

To solve the bottleneck, modern systems (like YouTube, TikTok, and Netflix) split the recommendation engine into a multi-stage funnel[cite: 8]. We trade absolute precision at the top for blazing speed, and save the heavy ML for the very bottom[cite: 8].

1. Candidate Generation
Extremely fast, lightweight algorithms that trim billions of videos down to a few hundred. High recall, low precision[cite: 8].
1,000,000,000 → 1,000
↓
2. ML Ranking
The heavy, precise Neural Network. It scores the remaining 1,000 videos to find the perfect matches[cite: 8].
1,000 → 50
↓
3. Re-Ranking
Final business logic. Removes clickbait, ensures diversity (so you don't get 50 identical videos), and inserts Ads[cite: 8].
50 → Top 10 UI

Phase 1 Deep Dive

3. Phase 1: Candidate Generation (Heuristics)

How do we instantly filter billions of videos down to 1,000 without using heavy ML? We use simple ideas, also known as Heuristics[cite: 8, 9].

💡
The "MrBeast" Heuristic: The simple idea that if a user is subscribed to MrBeast, there is a very high chance they want to watch MrBeast's new video[cite: 8]. We don't need AI to figure that out, we just need a database query[cite: 9].

We generate candidates using multiple fast, parallel database queries[cite: 9]:

  • Content-Based: SELECT * FROM videos WHERE channel_id IN (User Subscriptions)[cite: 8]
  • Trending: SELECT * FROM videos WHERE status = 'Trending' LIMIT 100[cite: 8]
  • Collaborative Filtering: Finding "Videos watched by similar users"[cite: 9]. (e.g., User A and User B both watch Tech videos. User B watched a new keyboard review. Recommend it to User A).

While database queries are great, the modern industry standard for finding "Similar videos to what I liked"[cite: 9] is shifting entirely to Vector Embeddings.

Going One Step Further

4. Embeddings & The Two-Tower Model

Machine Learning models cannot "watch" a video or "interview" a user. They only understand arrays of numbers. An embedding is a process that compresses the "meaning" of a video (its title, tags, thumbnail) into an array of floats (e.g., [0.9, 1.5, -2.8])[cite: 9, 10].

To do this at scale, companies use a Two-Tower Neural Network:

Because they are just coordinates in space, we can plot them mathematically. The Dot Product of the User Embedding and the Video Embedding gives us a similarity score. Videos that are conceptually similar (pets) physically group together in the vector space, while unrelated videos (chess) are pushed far away[cite: 9].

Interactive Architecture

5. Vector Databases & Nearest Neighbors

Once we turn billions of videos into embeddings, we store them in a specialized Vector Database (like Pinecone, Milvus, or pgvector)[cite: 10].

Traditional SQL databases are terrible at finding "points close to other points in 768-dimensional space." Vector databases are built specifically for this[cite: 10]. They use Hierarchical algorithms (like HNSW - Hierarchical Navigable Small World) to index the space, allowing them to find the "Nearest Neighbors" blazingly fast[cite: 10].

Phase 2

6. ML Ranking & The Clickbait Epidemic

Once our Candidate Generation funnel (Heuristics + Vector DB) returns ~1,000 highly relevant videos, we finally pass them to the heavy ML Ranking model[cite: 8].

This model evaluates hundreds of dense features to assign a final score:

  • User Context: Is it 9 AM on a Tuesday (show educational content), or 11 PM on a Friday (show entertainment)?
  • Video Metadata: How fresh is the video? What is its historical Click-Through Rate (CTR)?
⚠️
The Clickbait Problem: In the early 2010s, YouTube's objective function was purely optimized to maximize "Clicks". Creators realized this and started exploiting the algorithm with wildly misleading thumbnails and ALL CAPS TITLES.

To fix this, modern ranking models optimize for Expected Watch Time and post-video Survey Satisfaction to ensure long-term user retention, heavily penalizing videos where users click and immediately bounce.

Edge Cases

7. The Cold Start Problem

What happens when a new creator uploads a video? It has 0 views, 0 clicks, and 0 watch time. The ML Ranking model has no historical data to score it with.

🎮 NEW CREATOR EXPERIENCE
New YouTuber uploading their first Minecraft let's play, expecting the algorithm to push it to millions.
The ML Algorithm holding a spatula: "Just put the fries in the bag bro." 🍟

To solve the Cold Start Problem, systems use an "Explore & Exploit" strategy:

  • Explore: The system takes a calculated risk and forcibly injects the new video into the feeds of a small test group of users (based purely on the Video Tower's text embedding of the title/tags).
  • Exploit: If that small test group clicks and watches the video, the system immediately updates the video's CTR and Watch Time metrics, allowing the standard Ranking model to pick it up and push it to a wider audience.

Knowledge Verification

8. Architecture Quiz 🧪

0 / 3
1. Why do modern recommendation systems use a multi-stage funnel instead of just one giant ML model?
✓ Performance constraints. A heavy ML model would take days to score billions of videos for a single user[cite: 14]. The funnel architecture solves this by aggressively trimming the dataset first.
2. What is an "Embedding" in the context of the Two-Tower Model?
✓ Mathematical representation. Embeddings turn concepts into math. If a User Embedding closely matches a Video Embedding (their dot product is high), they are a good match[cite: 9].
3. Why are Vector Databases superior to standard SQL databases for finding similar videos?
✓ Hierarchical algorithms. Standard databases require O(N) linear scans to compare multi-dimensional floats. Vector DBs use HNSW to traverse graphs and find nearest neighbors much faster[cite: 10].
